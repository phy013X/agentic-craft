# 并行开发指南

vibecoding 时代的"并行"有四种形态，风险与纪律不同。先认清你在做哪一种，再套对应规则。通用原则一句话：**隔离优于协调，接口先行，小步集成，各自验证。**

## 形态 1：单人 + 多个 AI agent 并行（最常见）

你开多个 AI 窗口，或让一个 agent 派多个 subagent，同时推进几个任务。

### 核心风险
- 多个 agent 改同一文件 → 互相覆盖/冲突。
- 共享资源（端口、临时目录、全局配置、`process.env`）互相干扰，出现"单独跑都过、一起跑就挂"。
- 各线单独都绿，集成时才发现接口不兼容。

### 纪律
1. **按 worktree 隔离，而不是在同一目录切分支**
   ```sh
   git worktree add ../proj-feat-x feat/x     # 每个并行任务一个独立工作区
   ```
   各 worktree 有独立的依赖、构建产物、端口。**不要在同一工作目录里边切分支边跑并行任务**——AI agent 很容易在你切走的分支上继续写。
2. **按文件/模块给任务划边界**：派活前明确"这个 agent 只碰这些文件"。两个 agent 不要同时写同一文件；共享的类型/接口/配置由你先定好再分派。
3. **共享资源显式分配**：不同 worktree 用不同端口段；临时目录用 `mkdtemp` 而非固定路径；不要并行改全局配置/环境变量。
4. **各自验证再集成**：每条线在自己的 worktree 里跑自己的测试，绿了再合并。
5. **小步集成，不憋大招**：任务一完成就合，避免 5 条并行线憋一周后一次性合并（集成地狱）。

## 形态 2：多人 + AI 混合

= 形态 1 的全部纪律 + 传统协作：
- **CODEOWNERS** 明确每块代码的 owner，评审走 owner 而非任意人。
- PR 模板里的 **AI Usage** 标注各阶段 AI 参与度，高自动化改动配更严的人审。
- 铁律不变：人读懂 diff 才合并。

## 形态 3：stacked PR（依赖型并行）

把一个大改动拆成有依赖的 `A ← B ← C` 多个 PR，逐层评审、逐层落地。

### 工具
GitHub 官方扩展（需服务端 stack 功能支持）：
```sh
gh extension install github/gh-stack
gh stack --version    # 不可用就 hard-stop，别退回手工逐个 merge+retarget
```

### 纪律（提炼自 dsh）
1. **只用官方 `gh stack`** 落地，不用 `gh pr merge` + `gh pr edit` 手工改 base——手工 retarget 是 stacked PR 出错的主因。
2. 在**干净的专用 worktree** 里操作。
3. 拉取**精确 OID**（`headRefOid`/`baseRefOid`），不要只信分支名或旧报告。
4. `gh stack sync` 级联 rebase 后，**立即对每一层重跑相关检查**，全绿才允许合并。
5. 历史改写过用 `--force-with-lease=<精确OID>`，**绝不裸 `--force`**、绝不覆盖别人已推进的远端。
6. 合并后逐层确认 `MERGED`；删分支前确认没有任何开放 PR 仍以它为 base。

### 何时用 / 不用
- **用**：大改动需要分阶段评审、有明确依赖链、团队熟悉 rebase。
- **不用**：简单改动直接一个 PR；团队不熟 rebase 就拆成相互独立的 PR，或用 merge-forward。

## 形态 4：AI agent 内部的 fan-out（派 subagent）

一个主 agent 派多个 subagent 并行研究或实现。

### 纪律
- **只读研究类**（查资料、读代码、找方案）可以放心并行，无冲突。
- **写代码的 subagent** 必须按文件隔离，各自边界写清楚。
- 明确每个 subagent 的范围与产出格式；主 agent 负责集成、解决冲突、跑最终验证。
- 别让多个 subagent 改同一文件，也别让 subagent 之间隐式共享可变状态。

## 通用并行纪律（任何形态）

| 原则 | 含义 |
|---|---|
| 隔离优于协调 | worktree > 分支 > 目录；能物理隔离就不靠口头约定 |
| 接口先行 | 并行前先定好共享的类型/契约/配置，再分头实现 |
| 小步集成 | 每条线尽快合并，降低集成成本 |
| 各自验证 | 每条并行线独立跑自己的测试 |
| 共享资源显式分配 | 端口、路径、全局状态、数据库都要显式划分 |

## 工具速查

| 需求 | 工具 |
|---|---|
| 多任务物理隔离 | `git worktree` |
| 依赖型 PR 链 | `gh stack`（GitHub 官方扩展） |
| AI 内部并行 | Claude Code subagent / Task |
| 冲突预防 | CODEOWNERS + 文件级任务边界 |
