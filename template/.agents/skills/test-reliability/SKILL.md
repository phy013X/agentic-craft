# 测试可靠性

让测试在**真实 CI 拓扑**下也正确，而不只是在安静本机单独跑时正确。

## 资源原子分配

- 用资源 owner 的分配器，**绝不"先查空闲再占用"**。
- 网络：loopback `listen(0)`，在 server 报告 listening 后才读实际地址。**绝不先扫空闲端口再绑定。**
- 临时目录用 `mkdtemp`；共享数据库/socket/会话/输出位置用**每测试唯一命名空间**；路径需不存在时用独占创建。

## 容纳进程全局态

- 把 `process.env`、`cwd`、fake timers、locale/时区、模块 mock、注册表、`globalThis`、全局 `fetch` 拦截当作**独占可变资源**。
- 优先注入依赖/实例级适配器。必须改全局时：捕获原值（含"原本不存在"）→ **立即注册恢复** → 用最小 `try/finally` 包裹 → 失败可能早于 finally 时保留 `afterEach` 兜底 → 只拦截你拥有的最窄目标。

## 平台语义

- Windows 句柄**异步释放**：POSIX 上立即完成的 rename/删除，在 Windows 需要按实测争用做有界重试。
- Windows 无 POSIX 权限/信号语义：依赖它的用例**显式平台跳过并注明原因**，而不是在各处弱化断言。
- 环境变量名在 Windows 大小写不敏感；时间精度依文件系统而异——断言依赖"写回"时，从**重新读取**取期望值而非记住的值。

## 按状态同步，不靠 sleep

- 固定 sleep 不是"就绪"或"已清理"的证据。等**显式就绪事件/握手/状态迁移/自有 promise/外部可观察条件**。
- 超时只用于给等待设上限，**绝不作为让断言正确的条件**。
- 时间是主题时注入/fake 时钟，并总是恢复真实 timer。

## 拆除到静止

- 获取资源后**立即注册清理**，让断言失败也能释放。清理要停新回调、摘监听、恢复全局钩子、终止自有工作，并 **await 子进程退出 / server close / worker 终止**等完成信号。
- 只调 `abort()/close()/kill()` 而不 await 完成信号 = 拆除不完整。

## 拒绝"掩盖 flaky"的假修复

不要把下列当作确定性修复：**加超时（没找到真正等待的状态）、加重试、全串行、吞错/吞 unhandled rejection、弱化断言、normalize 掉不稳定、清理或断言前加 sleep**。
（真实外部 provider 的偶发抖动，其重试只留在外部边界。）

## 证明与诊断

- 新 guard：**故意注入坏案例，亲眼看它红**（负对照）。
- 竞态：用 barrier 证明重叠，**反复执行不是竞态测试**。
- 跨进程隔离：用独立进程并发验证端口/共享路径/子进程。
- 验证**外部状态**（文件/日志/事件/退出码/释放），而非被测者自报。
- 报告实际跑过的命令与结果；**重试通过、跳过、pending 的 CI 都不算"通过"**。
