# 性能优化

把"让它更快"变成**可复现的用户路径测量 + 小的、有证据的修复**。广泛调查、跟随实测成本、拒绝"看起来好但不改善真实负载"的改动。

## 先定边界

- 约定：**用户可见端点、工作负载范围、资源约束、可接受的微小行为差异、停止规则**。
- 后端与浏览器端到端测量**分开**；排除网络/模型延迟时要**显式声明**"这不是完整产品延迟"。
- 区分证据来源：已合并 / 被否 / 估算 / 新测量，别拿 PR 描述当真实现状。

## 先建真实基准，再优化

- 用**固定、可复现的输入**（reviewed 常量/种子），不依赖用户私有数据或环境。变化真正独立的成本维度（字节数、事件数、记录数、节点数是不同的量），别把"大量相同小消息"当成"真实负载"。
- 记录测量卡：用户操作与完成条件、负载维度、入口路径（真实生产调用/构建产物）、计时范围与冷/暖态、内存口径、判定聚合与阈值、负对照、必须保持稳定的行为。
- 测量**发布形态**（构建产物、真实运行时），不是带 loader 开销的源码路径。不要为测量专门加生产导出。

## 先证明回归，再删工作

- 改代码前先跑**未优化的基线**，存下命令、版本、环境、负载维度、原始测量、结论。
- **一次只改一个因果因子**；改完同时跑聚焦场景和它的端到端父场景。
- **负对照**：收紧的断言在原实现（或人为 reintroduce 该成本）上必须失败。阈值宽到回归也能过 = 没有保护。
- 保留内存语义：跟踪"仍有对象可达"的**保留内存**，与瞬时压力分开。**更快但无界保留不是稳赢。**

## 保住行为

- 性能测量补充而不替代功能证据。保留输出、顺序、取消、并发、释放、原子发布、必要校验。**不许为达数字而截断历史、跳过结果、改生命周期语义。**
- 故意的微小可见差异要声明，并有对应的功能/快照验证。

## 拒绝与收尾

- **拒绝**：端到端收益消失、典型负载明显劣化、复杂度超过小收益、取消/保留/持久性解释不清的优化。
- 汇报格式：**负载 → 前后绝对值与比值 → 端点与内存语义 → 行为证据 → 负对照 → 实际跑过的检查 → 排除项**。
- 区分"作者自报历史数字 / 本地新测量 / CI 证据"。在约定范围处停手，留一个排序后的后续清单，别顺手追无关机会。
