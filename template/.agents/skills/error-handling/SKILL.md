# 错误处理

## 类型化、结构化的失败

- 预期失败要有**声明类型 + 稳定判别字段 + 与处理相关的细节**；保留 cause；机器标识与显示文案分离。
- **绝不靠解析错误消息字符串来路由处理逻辑**（消息会变、会本地化）。
- 未预期缺陷（如 `assertNever`）可保持普通 Error，但**containment 绝不能把它变成"成功"**。

## 捕获、恢复，还是停止

- 对每个失败，定义**处理与报告的归属、containment、保证**：哪些不变量仍成立、副作用是"无/部分/已提交/未知"、谁负责清理。后台任务同样承担这些义务。
- **catch 只限制异常传播，不限制已发生的 mutation**。只有受影响状态的 owner 能确定"安全续跑"；否则停止依赖工作、丢弃无效状态/实例、或上报。**光记日志不是恢复。**
- **重试**需要：可安全重复 + 可取消 + 有明确 owner + 有预算（有限操作给次数/时间预算；持续监督要有生命周期归属和可观测的降级）。

## 本地化、可行动、可见的报告

- 每个最终报告要含：**可读摘要 + 受影响的操作 + 安全的下一步**。敏感内部细节不进用户可见文案。
- **不信任状态或未知结果必须可见**（UI 或默认开启的日志）：说明影响、不确定性、系统处置、安全下一步。持久存在的无效状态需要持久可见。
- **没有保证就不要声称**成功/已回滚/可安全重试。报告失败本身要有独立的兜底。

## 验证

- 验证**最终状态与可见结果**，而不只是"异常被捕获了"。
